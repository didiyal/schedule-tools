# v1.2 设计方案 — 筛选改造 · 分页加载 · 任务树 · CLI 同步

状态：设计稿（待评审后实施）
日期：2026-10-23
前置：v1.1.1 渲染管线（计划比较 + 三种物化路径）、v1.1.2 CLI（IPC + headless 双路径）

---

## 0. 背景与目标

| # | 需求 | 一句话方案 |
|---|------|-----------|
| 1 | 去掉 未完成/已完成/全部 三段切换；默认全部，用勾选筛选 | 分段按钮 → 两个勾选芯片（未完成/已完成），内部 `filter_state` 复用 |
| 2 | 全部页面分页加载，加快渲染 | 计划层截断每页 30 条卡片 + 「加载更多」/滚动到底自动追加 |
| 3 | 任务树：主任务 → 子任务 → 子子任务，新建默认主任务，可拖拽移动 | 数据层加 `parent_id`，渲染层缩进 + 折叠，拖拽三区落点（上/下=兄弟、中=成为子级） |
| 4 | CLI 同步更新 | `brief` 加 `parent/depth`，`add --parent`，新增 `reparent`，`delete` 语义改为删整枝，`list --tree` |

设计总原则：**尽量复用 v1.1.1 渲染管线**（entries 计划 → 同值守卫 → 插入/删除/全量三种物化路径），树和分页都落在「计划层」解决，物化层只做小改。

## 2. 分页加载

### 2.1 计划层截断

- `PAGE_SIZE = 30`（常量放 `constants.py`），**对所有列表视图生效**（全部/未完成/已完成共用管线；已完成历史最受益）。
- `MainApp.__init__` 增加 `self._page_limit = PAGE_SIZE`。
- `_compute_plan` 在分组、排序完成后截断：卡片条目数超过 `_page_limit` 时只保留前 N 条，并追加一个哨兵条目 `("more", 剩余条数)`。装饰（hdr/sub/empty）不占页容量。
- 新装饰控件 `LoadMoreHint`（`todo_card.py`，纯 tk，样式同 `EmptyHint`）：文案「加载更多（还有 N 项）」，点击回调 `MainApp._load_more`。

### 2.2 加载更多的两条触发路径

1. **点击按钮**：`_load_more()` → `self._page_limit += PAGE_SIZE` → `_refresh_view()`。
2. **滚动到底自动追加**：包装 `yscrollcommand`，当 `yview` 下沿 ≥ 0.98 且计划含 more 哨兵时，防抖 250ms 调 `_load_more`。

### 2.3 为什么追加是便宜的（复用插入路径）

`_page_limit` 增大后新计划是旧计划的**纯尾追加** → `_is_subsequence(old, new)` 成立 → 走现有 `insert` 原地路径：只有新卡片被创建并 pack，已渲染卡片一个不动。

唯一风险：一次 pack 30 张卡片 ≈ 30×15ms 同步开销。补一条规则：**insert 路径一次新增 > `INSERT_STREAM_MIN = 10` 张时，按每帧 10 张、间隔 16ms 分帧补齐**（复用 `_render_seq` 令牌与 `RENDER_BUDGET` 思路；新卡片都在尾部 `pack`，分帧不影响锚点逻辑）。

### 2.4 页容量重置时机

| 事件 | 是否重置 `_page_limit = PAGE_SIZE` |
|------|----------------------------------|
| 切换日期（‹ › / 今天） | ✅ |
| 勾选筛选变化 | ✅ |
| 搜索词变化 | ✅ |
| 数据增删改（add/done/drag…） | ❌（保留用户的浏览位置；卡片变少了自然小于页容量，无副作用） |

### 2.5 与既有机制的配合

- 流式首屏（`RENDER_FIRST_BATCH=14` + 预算分帧）保留：页容量截断后全量重排最多 30 张，流式仍是保险。
- 预热 `_prewarm_cards` 保留（空闲期 30ms/张）；当 todo 总量 > 200 时只预热前 200 张，避免启动后台负担无上限。
- `_card_cache` 不因翻页清理——翻页往返要瞬时，内存代价可接受。
- 与日组布局的配合：今日组在最前且通常最小，历史日期组垫在尾部按页懒加载——日常几乎只渲染今日工作集。

## 3. 任务树

### 3.1 数据模型

- `TodoWidget` 增加 `parent_id: str | None = None`；`set_parent(pid)` 赋值后 `_fire_change()`。
- 兄弟顺序沿用现有全局 `_order`（只在同一父下的兄弟间比较，不做 per-parent order，序列化/撤销快照零改动）。
- **深度上限 3 层**：root=0，子=1，孙=2；≥3 层的一切入枝操作（拖拽/缩进/CLI）拒绝。
- 序列化：`to_dict()` 增加 `"parent": self.parent_id`；`_load_todos` / `_add_todo` 透传。**纯增量字段**：旧版 EXE 读新文件忽略未知键；新版读旧文件默认 `None`。`archive.json` 不引入树概念（归档即拍平）。

### 3.2 不变量与装载校验

- 不变量：`parent_id` 要么 `None` 要么指向存在且**非自身后代**的 id；全树深度 ≤ 3。
- `_load_todos` 末尾跑一遍 `_normalize_parents()`：检测环、悬空引用、超深——把违规节点拍平为顶层。headless 写文件可能产生任意内容（外部脚本手改 JSON），GUI 装载时必须自愈，不能崩溃或死循环渲染。

### 3.3 纯函数模块 `src/tree.py`

供 GUI 与 headless 共用，操作 `{id: parent_id}` 映射（不依赖 TodoWidget，`cli_headless` 不得 import TodoWidget）：

```python
children_map(parents) -> {pid: [cid 按插入序]}      # 供 DFS
subtree_ids(parents, root) -> set[str]             # 整枝
depth_of(parents, tid) -> int
subtree_depth(parents, root) -> int                # 子树高度(层数)
can_adopt(parents, new_parent, dragged, cap=2) -> bool
                                                   # 非后代 + 深度不超限
dfs_order(parents, root_ids_sorted) -> [tid]       # 深度优先序列
```

### 3.4 渲染

**条目元组扩展**：`("card", tid, seq, show_date)` → `("card", tid, seq, show_date, depth, expandable, expanded)`。
计划比较是元组全等，扩展后自动兼容；fingerprint 增加 `w.parent_id`（parent 变化但 `_version` 未变的情况由 fingerprint 兜底）。

**卡片视觉**（`todo_card.py`）：

- 缩进：depth × 18px 左侧留白（content 前插一个固定宽度 spacer）。
- 折叠箭头：`expandable=True` 时序号前显示 `▸/▾`（纯 tk Label）；点击**只切换折叠、不选中卡片**（事件 `break` 阻断冒泡）。父卡片序号旁显示子进度 `2/5`（灰字）。
- 拖拽虚影文字带整枝规模：`✥ 文本（含 2 个子任务）`。

**树与日期分组的关系（关键规则）——树包含优先于日期分组**：

- 子树整体渲染在**根节点**所在位置，子任务不按自己的日期拆组；子任务日期 ≠ 父任务日期时显示 `[10月22日]` 角标（复用 `show_date`）。

**分组与排序（本节核心决策，2026-10-23 用户拍板：不分区，每日一棵树）**：

- 全部视图沿用**按日期倒序的日组**；每个日组内是当天根节点构成的**森林**，子树整体挂在根下（树包含优先，见上）。
- **排序与完成态完全解耦**：每层排序键 = `（非重点, order）`，完成/取消**不移动任何节点**——树序即用户排程序，永远稳定。
- 完成状态全靠**颜色**表达（用户拍板：完成的变绿、文字变灰）：
  - 完成卡片：**底色绿**（`C["green_light"]`）+ 绿色 accent 条 + `[已完成]` 绿字 + 文字与时间**灰显**（时间另加删除线，沿用现状）；
  - 未完成卡片：白底不变（不在面板的 ◌ 项文字灰，沿用现状）；
  - 底色优先级：选中（`blue_light`）> 完成（`green_light`）> 悬停（`bg`）> 白；完成卡不响应悬停变色；
  - 父卡片显示 `n/m` 子进度——整枝全完成时整棵树一片绿，一眼可见。

**完成/取消的视觉语义（回答「完成了会怎么变」）**：

| 动作 | 视觉变化 |
|------|---------|
| 完成叶节点 | **原位变绿变灰**，父卡片进度 `n/m` 更新，位置、日组、兄弟序全不动 |
| 完成枝内最后一个未完成节点 | 整枝原位全绿（无任何移动） |
| 完成无子节点的主任务 | 原位变绿（不再沉底） |
| 全部子完成、父未完成 | 子全绿，父仍白底带 `n/m` 提醒收尾 |
| 取消完成 | 原位恢复白底黑字（取消不还原原日期，沿用现状） |

**筛选保留规则（勾选与搜索统一为节点谓词）**：

> 节点满足谓词则保留；任一后代被保留，则其**祖先链**强制保留（灰显撑结构）；其余丢弃。

- 勾`未完成`：谓词=未完成 → 只剩还挂着的活（整枝完成的消失；活跃父下的已完成叶被剔除，父的 `n/m` 进度仍在）。
- 勾`已完成`：谓词=已完成 → 完成节点 + 其祖先链（**保留树形，不再拍平**）。
- 搜索：谓词=文本匹配，与上面勾选谓词叠加（AND）。
- 双勾 / 双不勾 = 无谓词 = 完整森林。
- 日期导航（‹ › / 今天）不改变分组集合（全部视图始终显示所有日期、今日组恒在最前），仅更新日期标题——与现状一致。

**折叠状态**：`self._collapsed: set[str]`（默认全展开）；持久化到 `todos.json` 顶层 `"collapsed": [id...]`（随 `_save`/`_load_todos` 读写，默认展开）。

**序号**：沿用现状——组内可见卡片连续编号，不按层级重排。

### 3.5 交互

**增**：
- 右键菜单新增「➕ 添加子任务」→ 小对话框输入文本 → 创建子任务（日期继承父任务），父节点自动展开。
- 新建任务（顶部输入框 / CLI add）默认顶层主任务，不变。

**改层级（拖拽之外的键盘/菜单路径，拖拽难精确，必须有）**：
- 选中卡片 + `Tab` = 降为上一兄弟的最后一个子任务（`can_adopt` 校验）。
- 选中卡片 + `Shift+Tab` = 提升：成为父节点的下一个兄弟。
- 右键菜单同款两项「降为子任务 / 提升层级」。操作对象均含整枝（后代跟随）。

**拖拽（三区落点，Workflowy 风格）**：指针在目标卡片矩形内的纵向位置分三区——
| 区 | 落点语义 | 指示器 |
|----|---------|--------|
| 上 25% | 插到其上方（同父兄弟序） | 蓝色横线（与卡片同缩进） |
| 下 25% | 插到其下方（同父兄弟序） | 蓝色横线 |
| 中 50% | 成为它的子任务（挂末尾） | 绿色横线（缩进 +18px）；目标卡片边框高亮 |

约束：
- 兄弟插入仅限**与被拖节点同父**的目标（顶层维持现有「同日期组」规则）；不同父 → 无指示器，松手弹回。
- 成为子级：目标不能是被拖节点的后代（成环）；`目标depth + 1 + 被拖子树高度 ≤ 3`。
- 整枝移动：后代由数据派生，天然跟随，无需额外处理。
- 拖拽落点计算基于当前已物化卡片（分页窗口内）——跨页边界的兄弟位置拖拽不可达，属可接受限制；翻页后自然可达。

**删**：
- 删除含子节点的任务 = **删除整枝**（确认对话框列出「及其 N 个子任务」；Ctrl+Z 撤销快照保存整枝全部条目）。
- 「清除已完成」归档：只归档已完成节点；被归档节点的未完成后代**上抛给祖父**（与整枝删除不同：归档是清理已完结工作，要保留未完结的）。

**完成**：父子独立完成（不级联）——子任务有独立计时，自动连坐会误伤。父卡片显示子进度 `2/5` 提供汇总感。

**计时面板**：完全不受影响（面板是平铺设计，按需 add/remove）。

### 3.6 与既有机制的兼容

| 机制 | 影响 |
|------|------|
| 计划比较 | entries 元组扩展后仍是纯数据全等，零改动 |
| insert/delete 原地路径 | 折叠=纯删（子序列成立）、展开=纯插，自动走便宜路径 |
| 选中保留 | 子树折叠后选中的卡片不在渲染集 → 现有「不在 card_tids 则清空」规则天然覆盖 |
| 主 Tick | 遍历 `self._cards`（可见卡片），折叠的运行中卡片不刷但面板刷，无影响 |
| `_key_move` | 按 `_cards` 顺序导航 = DFS 显示序，天然正确 |
| 拖拽指示线/虚影 | 复用现有 Toplevel 机制，加缩进与绿色样式 |

## 4. CLI 同步

### 4.1 输出结构

`brief`（GUI `_cli_brief` 与 headless `brief` 同构）增加：

```json
{ "parent": "12" | null, "depth": 0 }
```

`--json` 的 list 保持**扁平列表 + parent 指针**（不嵌套）——扁平对 Agent 解析/过滤最友好，树可自行重建；人类可读场景用 `--tree`。

### 4.2 命令变化

```bash
todo_cli.py list --tree                    # 树形缩进输出（文本模式）
todo_cli.py add "任务" --parent 12         # 创建为 #12 的最后一个子任务
todo_cli.py reparent 15 --parent 12        # 移动到 #12 下（整枝）
todo_cli.py reparent 15 --top              # 提为顶层
todo_cli.py delete 12                      # 删除 #12 及其整枝（回显删除条数）
```

- `list` / `list --tree` 排序改为 **DFS 森林序**（日组倒序；组内/枝内按 `重点 → order`，与完成态无关），与 GUI 显示顺序一致——替代现在的 `(completed, not starred, order)` 平铺排序，父子相邻是硬要求。
- `reparent` 校验：目标存在、非后代、深度 ≤ 3；违规返回 `ok:false` + 原因。
- `delete` 语义变化要写进帮助文本与 CHANGELOG（破坏性变更：以前只删单条）。
- `done` 不级联（与 GUI 一致）。
- IPC 与 headless 两条路径同步实现；`cli_headless.apply` 新增 `reparent`/`add.parent`，`list_items` 排序改 DFS（用 `tree.py` 纯函数）。

### 4.3 文本树输出样式（print_list --tree）

```
待办 (2026-10-23) — 5 项
  #12   [运行中] ★ 写周报 2/5   00:12:33
  #15     ├─ 收集数据           00:03:00
  #16     └─ 写正文             00:09:33
  #20   [暂停] 修登录 bug       00:41:00
```

## 7. 风险与已知坑对照

- CTk `configure` 同值重绘 → 折叠箭头/进度标签全部走同值守卫（现有模式照抄）。
- insert 分帧期间用户再操作 → 复用 `_render_seq` 令牌，新计划直接作废旧流。
- 滚动到底自动加载与 scrollregion 50ms 合并并存 → `_load_more` 后 scrollregion 只重算一两次，无 7 倍放大回归。
- 树 + 搜索 + 完成态组合的筛选保留规则必须在 `_compute_plan` 纯计算层实现（可单测），不碰控件。
- headless 与 GUI 语义必须一致：`tree.py` 共享纯函数，两边各自只写「取 parents 映射」的适配器。
- UI 层 bug 在逻辑层复现不出来 → 拖拽三区落点、折叠点击必须走 GUI 自动化真实点击验证。
- 完成/取消只变色不移动 → entries 序列不变，走 "same" 原地路径逐卡同步；同值守卫保证只有变色的卡片重绘（比现状组内重排更便宜）。

## 8. 测试要点（对应 docs/development 测试策略）

1. 筛选四态 × 视图标题/分组正确性；双勾 = 全部。
2. 分页：31 条 → 首页 30 + 剩余 1；加载更多 insert 路径不重排已有卡片（截图对比 + 逐卡 id 断言）；页容量在切日期/筛选/搜索时重置、在数据变更时保留。
3. 树：
   - 装载校验：手造环/悬空/超深 JSON → GUI 正常启动，违规拍平。
   - 折叠/展开走 insert/delete 原地路径（性能不退化）。
   - 拖拽三区 × 有效/无效目标（成环、超深、跨父）矩阵（可用 allpairs 生成）。
   - 完成不变序：完成叶/整枝 → 位置与兄弟序不动、卡片变绿；Ctrl+Z 回白；勾选未完成/已完成时祖先链灰显保留、非匹配叶被剔除。
   - 删除整枝 + Ctrl+Z 撤销还原整枝。
   - 归档已完成父 → 未完成子上抛祖父。
4. CLI：IPC 与 `--headless` 双路径对 `add --parent / reparent / delete --tree / list --tree` 结果一致；旧格式文件无损升级。
